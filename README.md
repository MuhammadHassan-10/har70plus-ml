## 🔍 Overview

This project implements a complete, end-to-end machine learning pipeline for **Human Activity Recognition (HAR)** on the **HAR70+** dataset — wearable accelerometer recordings from 18 older adults (ages 70–95). Unlike most HAR work that targets younger populations, this pipeline is specifically designed for the clinical challenges of elderly subjects: irregular gait, use of walking aids, severe class imbalance, and the need for interpretable predictions.

### What makes this different from standard HAR pipelines:

| Challenge | Our Solution |
|---|---|
| Subject identity leakage | `GroupShuffleSplit` — test subjects never in training |
| Class imbalance (stairs < 0.2%) | `SMOTE` applied on training set only |
| Overly optimistic CV | `GroupKFold` — subject-aware 5-fold CV |
| Black-box predictions | `SHAP TreeExplainer` — feature-level clinical explanations |
| Deep learning baseline | Classical ML surpasses CNN-LSTM (96.9% vs 94.7%) |

## 🏗️ Pipeline Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                    HAR70+ PIPELINE  v3.0                        │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  18 CSV files (501–518)                                          │
│       ↓  Sort by subject + timestamp                             │
│                                                                   │
│  Sliding Window (100 samples = 2s @ 50Hz, 50% overlap)          │
│       ↓  Skip cross-subject boundary windows                     │
│       ↓  Majority-vote labelling                                 │
│       ↓  45,157 windows  ×  134 features each                   │
│                                                                   │
│  GroupShuffleSplit  →  80% train / 20% test (subject-disjoint)  │
│       ↓  StandardScaler  (fit on train only)                     │
│                                                                   │
│  5-fold GroupKFold CV  (pre-SMOTE, honest evaluation)           │
│       ↓                                                           │
│  SMOTE  (training set only → fixes 0.2% stair minority)        │
│                                                                   │
│  ┌─────────────────┬───────────────┬──────────────────┐         │
│  │  Random Forest  │  XGBoost ✓   │   SVM (RBF+PCA)  │  Super. │
│  └─────────────────┴───────────────┴──────────────────┘         │
│                                                                   │
│  ┌─────────────────────────┬──────────────────────────┐         │
│  │  KMeans (K=7, top-10)  │  DBSCAN (eps=1.2, top-10)│  Unsup. │
│  └─────────────────────────┴──────────────────────────┘         │
│                                                                   │
│  SHAP TreeExplainer  →  beeswarm · per-class bar · waterfall    │
│                                                                   │
│  28 plots  ·  best_model.pkl  ·  scaler.pkl  ·  Streamlit App  │
└─────────────────────────────────────────────────────────────────┘
```

## ▶️ How to Run

### Step 1 — Run the full ML pipeline

```bash
python har70_pipeline_FINAL.py
```

This will:
- Load and preprocess all 18 subject CSVs
- Extract 134 features across 45,157 sliding windows
- Train and evaluate RF, XGBoost, and SVM with GroupKFold CV
- Run KMeans and DBSCAN clustering
- Generate SHAP explanations
- Save 28 plots to `./har70_output/plots/`
- Save `best_model.pkl`, `scaler.pkl`, `label_encoder.pkl`, `feature_names.pkl`

> ⏱️ Runtime: approximately 25–40 minutes on a standard laptop CPU.

### Step 2 — Launch the Streamlit demo

```bash
streamlit run har70_app.py
```

Opens at `http://localhost:8501` in your browser.

> **Note:** Run the pipeline first. The app requires the saved model artifacts in `./har70_output/`.

## 🔢 Features Extracted

Each 2-second window (100 samples) yields **134 features**:

### Time-Domain (96 features — 16 per sensor axis × 6 axes)
`mean` · `std` · `min` · `max` · `range` · `median` · `Q25` · `Q75` · `IQR` · `skewness` · `kurtosis` · `energy` · `RMS` · `MAD` · `zero-crossing rate` · `variance`

### Frequency-Domain via Welch PSD (24 features — 4 per axis × 6 axes)
`PSD mean` · `PSD max` · `dominant frequency` · `spectral entropy`

### Cross-Sensor Features (14 features)
`back_mag_mean/std/max` · `thigh_mag_mean/std/max` · `mag_diff_mean` · `mag_corr` · `back_xy/xz/yz_corr` · `thigh_xy/xz/yz_corr`

## 🎯 Key Design Decisions

### Why GroupShuffleSplit instead of random split?
Each subject has a unique gait signature embedded in every feature. A random split allows windows from subject 505's session to appear in both training and test sets — the model memorises their personal walking pattern and achieves artificially high accuracy. `GroupShuffleSplit` guarantees complete subject disjointness.

### Why SMOTE only on the training set?
The test set must reflect real-world class proportions to give honest evaluation. Oversampling test data would evaluate the model on a distribution that doesn't exist clinically. SMOTE is applied after the split, before fitting only.

### Why GroupKFold instead of StratifiedKFold?
Stratified folds balance class proportions but ignore subjects — the same subject can appear in training and validation of the same fold, leaking identity information into CV scores. `GroupKFold` respects subject boundaries in every fold.

### Why classical ML over deep learning?
XGBoost (96.9%) outperforms the published CNN-LSTM baseline (94.7%) on this dataset while: requiring no GPU, training in minutes, providing full SHAP interpretability, and being deployable without a deep learning framework. For well-curated sensor data with strong feature engineering, deep learning offers no accuracy advantage.

### Why top-10 features for clustering?
In 134-dimensional feature space, all pairwise distances converge (curse of dimensionality), making KMeans and DBSCAN distance metrics unreliable. The top-10 XGBoost features concentrate the most discriminative signal, producing cleaner cluster geometry.

## 💡 SHAP Clinical Insights

| Activity | Key Feature | Physical Interpretation |
|---|---|---|
| 🛌 Lying | `back_x_mean ≈ 1.0g` | Sensor lying flat — forward axis aligns with gravity |
| 🪑 Sitting | `thigh_x_mean ≈ 0.85g` | Thigh horizontal — gravitational load on thigh sensor |
| 🧍 Standing | `back_z_mean ≈ 1.0g` | Upright posture + near-zero std on all axes |
| 🚶 Walking | `dom_freq ≈ 1.8 Hz` | Periodic gait cycle at typical older adult cadence |
| ⬆️ Stairs Up | `thigh_mag_mean` high | Strong thigh flexion + elevated back energy |
| ⬇️ Stairs Down | `back_y_std` high | Forward lean instability + low thigh coordination |
| 🦯 Shuffling | `dom_freq ≈ 1.0 Hz` | Slower cadence, reduced oscillation amplitude |
| 🔑 Cross-sensor | `mag_corr` | Separates dynamic (walking) from static activities |
